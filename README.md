### Задание 2
Задание 2
Проведите сканирование Metasploitable в режимах SYN, FIN, Xmas, UDP.

Запишите сеансы сканирования в Wireshark.

Ответьте на следующие вопросы:
Чем отличаются эти режимы сканирования с точки зрения сетевого трафика?
Как отвечает сервер?

1. Запускаем Wireshark и затем запускаем сканирование nmap в режимах SYN, FIN, Xmas, UDP. Результат видим на скриншотах 2-5
2.
SYN‑сканирование (nmap -sS)
Трафик: Nmap отправляет TCP‑пакет с флагом SYN на целевой порт. Это «попытка установить соединение», но полноценное 3‑стороннее рукопожатие не завершается.
Особенности:
Минимальный объём трафика: по 1–2 пакета на порт (SYN → ответ).
Не оставляет «полноценного» соединения в логах приложений (только в сетевом стеке ОС).
Требует прав root (чтобы формировать «сырые» пакеты).
В Wireshark видно: TCP flags: SYN, затем SYN-ACK (порт открыт) или RST (порт закрыт).

FIN‑сканирование (nmap -sF)
Трафик: отправляются TCP‑пакеты только с флагом FIN (обычно используется при корректном закрытии соединения).
Особенности:
Ещё меньше «типичного» трафика для сканирования портов: нет SYN, нет полноценного соединения.
Работает по RFC: закрытые порты отвечают RST, открытые — часто молча игнорируют «некорректный» FIN без установленного соединения.
На некоторых ОС (например, Windows) логика отличается: открытые порты тоже могут отвечать RST, поэтому точность ниже. На Linux (как Metasploitable) метод работает лучше.
В Wireshark: TCP flags: FIN, далее либо RST, либо тишина.

Xmas‑сканирование (nmap -sX)
Трафик: пакеты с комбинацией флагов FIN + PSH + URG (отсюда название «рождественский»).
Особенности:
Это «аномальные» пакеты: в нормальном TCP‑трафике такая комбинация почти не встречается.
Цель — вызвать специфическую реакцию стека TCP/IP и обойти простые фильтры/IDS, которые ищут только SYN.
Логика ответа та же, что у FIN: закрытые порты — RST, открытые — игнорирование.
В Wireshark легко отличить по флагам: FIN, PSH, URG одновременно.

UDP‑сканирование (nmap -sU)
Трафик принципиально другой: используется протокол UDP, у которого нет флагов и «рукопожатия».
Как это выглядит:

Nmap шлёт пустой UDP‑пакет (или специфичный для сервиса) на порт.
Если порт закрыт, ОС цели отвечает ICMP‑сообщением Port Unreachable (ICMP type 3, code 3).
Если порт открыт, сервис может ответить своим UDP‑пакетом (например, DNS‑ответ, SNMP‑ответ).
Если нет ответа — Nmap помечает порт как open|filtered (неясно: открыт или заблокирован фаерволом).
Трафик заметно «тяжелее»: на каждый порт может уходить несколько попыток и ждать таймауты (поэтому UDP‑сканирование медленное).
В Wireshark: пакеты UDP и/или ICMP Destination Unreachable.
